# 摄影页面与 Notion 图片管理

访问地址：`/photography`。布局来自 `photogra/custom.css`，转换为路由隔离的 CSS Modules；交互用 React 实现，不需要把参考目录的脚本追加到全站 custom.js。

## 1. 在博客主管理数据库添加导航入口

使用你现有的 NotionNext 主数据库，保持以下两条记录相邻：

| title  | type    | status    | slug         |
| ------ | ------- | --------- | ------------ |
| 收藏集 | Menu    | Published | #            |
| 摄影   | SubMenu | Published | /photography |

`SubMenu` 归属它上方最近的 `Menu`；将摄影放在收藏集的其他子菜单之间即可。等待博客原有缓存刷新，导航就会显示“收藏集 → 摄影”。页面已由代码提供，不需要额外创建 slug 同名的 Page 记录。

Hexo 桌面和移动导航已有兜底入口；如果 Notion 里已有“摄影”，会使用这一条并更新到 `/photography`，不会再新增一条。

## 2. 新建独立的“摄影作品”数据库

在你的 Notion 主管理页面下新建一个**完整数据库**，命名“摄影作品”。不要把照片作为博客主数据库里的 Post。

按下面的名称和类型创建属性（名称需一致）：

| 属性名 | Notion 类型                | 使用方式                              |
| ------ | -------------------------- | ------------------------------------- |
| 标题   | 标题 / Title               | 照片名称                              |
| 照片   | 文件和媒体 / Files & media | 上传一张照片；也可添加 HTTPS 图床链接 |
| 分类   | 选择 / Select              | 街拍、人像、风光、随拍                |
| 排序   | 数字 / Number              | 10、20、30…，数字越小越靠前           |
| 发布   | 复选框 / Checkbox          | 勾选展示，取消勾选隐藏                |

每条记录展示“照片”属性中的第一张图。建议一张照片一条记录，发布前填写排序。分类留空时归入“随拍”，未上传照片的记录不展示。可以添加“拍摄时间”“地点”等私人管理字段，接口不会输出这些字段。

推荐建立两个视图：

- **作品库**：Gallery 画廊视图，卡片预览选择“照片”，显示标题/分类/发布，按排序升序。
- **待发布**：表格或画廊视图，筛选“发布未勾选”，集中管理草稿。

日常操作：新建记录 → 上传照片 → 填标题/分类/排序 → 勾选发布。无需编辑代码或重新部署。取消发布用于下架；图片文件请保留在 Notion 中，不要复制临时链接后删除原文件。Notion 的图片上传大小限制取决于你的套餐。

## 3. 配置只读连接（一次性）

1. 打开 https://www.notion.so/profile/integrations，新建内部 Integration，选择数据库所在工作区，只开启读取内容权限。
2. 回到“摄影作品”数据库，右上角 `… → Connections / 连接`，添加这个 Integration。数据库无需发布到互联网。
3. 复制数据库链接，其中路径末尾的 32 位 ID 是数据库 ID；不要复制 `?v=` 后的视图 ID。此版本使用仓库已有的 Notion SDK，使用单一数据源数据库；不要在该数据库容器中加入多个数据源。
4. 本地 `.env.local` 中填写（该文件已被 Git 忽略）：

```dotenv
PHOTOGRAPHY_NOTION_TOKEN=你的内部Integration密钥
PHOTOGRAPHY_NOTION_DATABASE_ID=你的数据库ID
```

5. 在 Vercel 项目的 Environment Variables 添加相同两项，首次配置后重新部署。本地开发服务器也需要重启。密钥不要加 `NEXT_PUBLIC_` 前缀，也不要写进 Notion 正文或提交 Git。

## 同步与错误处理

摄影页请求 `/api/photography`，服务端只读已发布记录，支持分页读取，按排序升序、创建时间降序排列。服务端缓存最多 45 秒（签名链接即将过期会提前失效），浏览器每 60 秒及重新回到标签页时刷新。常规修改在约 1–2 分钟内可见，刷新网页也可拉取；Notion 故障或限流时会显示重试提示。公开接口只提供 id、图片链接、标题、分类。

Notion 托管图片的临时 URL 会随同步重新获取。原文件仍在 Notion，访客始终只读。隐藏/删除作品是下架操作，不会收回别人已经保存或缓存的图片。

开发环境未配置两项变量时，使用 `lib/photography/sample.json` 的示例图片用于排版预览。生产默认不使用示例图；只有主动设置 `PHOTOGRAPHY_DEMO=true` 且未填写任何数据库配置时才展示示例图。真实数据库为空或请求失败不会回退到示例图。

需要支持 Next.js API 的部署环境（如 Vercel、Node）。纯静态 `next export` 无法运行 Notion 同步接口。
